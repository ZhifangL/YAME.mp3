# YAME — engine (mp3-metadata-api)

FastAPI service that reads/writes audio metadata and runs the YAME
rules engine. In dev it serves the React frontend over HTTP on
`127.0.0.1:8000`; in the packaged Tauri app it ships as a Python sidecar.

## Run

```bash
uv sync                      # first time only (includes the dev/test tools)
.venv/bin/python main.py     # picks a free port (8000 unless taken)
.venv/bin/uvicorn main:app --port 8000
```

- Interactive docs: <http://127.0.0.1:8000/docs>
- Health check: `curl http://127.0.0.1:8000/api/health`
  (also reports `config_dir`, so the UI never has to guess where presets live)

> The API reads/writes local files by absolute path and must stay bound to
> 127.0.0.1 only.

## Tests

```bash
.venv/bin/python -m pytest        # 101 tests, no fixtures on disk
```

Covers the wildcard layer, all nine rules, ruleset ordering and
cover composition, the rename rules (extension retention, collisions, refusing
to escape the folder), read/write/cover round-trips, and the HTTP contract the
React frontend depends on. Audio files are generated by the suite itself, so it
never touches the sample folders.

## Shipping as a sidecar

The desktop app bundles this engine as a single PyInstaller binary:

```bash
.venv/bin/pyinstaller yame-engine.spec --noconfirm
```

`yame-engine.spec` collects uvicorn's dynamically-resolved loop/protocol
modules, which static analysis cannot see. `../mp3-desktop-frontend/scripts/
build-sidecar.sh` runs this and copies the result to the target-triple name
Tauri's `externalBin` requires. PyInstaller does not cross-compile: build the
sidecar on each platform you ship.

## Layout

```
main.py                  entry point (uvicorn main:app); publishes the port on
                         startup, not on import
app/
  api.py                 app factory (CORS, routers, /api/health)
  schemas.py             pydantic request/response models (the JSON contract)
  fields.py              canonical field catalog (tag keys per format +
                         pseudo-fields like filename/folder)
  services/
    fs_browser.py        folder browsing -> folders + audio files
    audio_io.py          mutagen read/write for MP3/M4A/FLAC/OGG/WAV/AIFF/
                         APEv2 + WMA read-only, cover art, ruleset applier
    rules.py             the rules engine: CLEAR, REPLACE, WRITE, APPEND,
                         COPY FROM, PARSE FILENAME, CHANGE CASE, SET COVER,
                         REMOVE COVER
    presets.py           named rulesets as JSON in ~/.config/yame/
  routers/
    filesystem.py        GET /api/browse
    audio.py             everything else (see below)
tests/                   pytest suite
```

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Liveness, version, and the config dir |
| GET | `/api/browse?path=` | List folders + audio files |
| GET | `/api/metadata?path=` | Read one file (tags, stream info, cover) |
| POST | `/api/tracks/read` | Read many files at once (`tracks` + `errors`) |
| POST | `/api/tracks/write` | Write fields of one file (`rename_to` renames) |
| POST | `/api/tracks/cover` | Replace or remove (`remove: true`) embedded cover art |
| GET | `/api/rules/registry` | Rule + field + audio-suffix catalog (the UI renders from this) |
| POST | `/api/preview` | Dry-run one rule on given field values |
| POST | `/api/apply` | Dry-run or apply a ruleset to many files |
| GET/PUT/DELETE | `/api/presets` | Named rulesets (JSON in `~/.config/yame/`) |
| POST | `/api/presets/import` | Import exported rulesets |

## Metadata response shape

```jsonc
{
  "file":    { "path", "filename", "size_bytes", "modified_unix", "created_unix" },
  "audio":   { "duration_seconds", "bitrate_kbps", "sample_rate_hz",
               "channels", "codec", "codec_detail", "mode", "bitrate_mode" },
  "fields":  { "title": "...", "artist": "...", "album": "...",
               "date": "...", "comment": "...", ... },   // canonical ids
  "cover":   { "mime": "image/jpeg", "data_base64": "..." } | null,
  "writable": true,
  "warnings": []
}
```

`POST /api/tracks/read` returns `{ "tracks": [...], "errors": [{ "path", "error" }] }`.
Both keys are declared in `TracksReadResponse` on purpose: FastAPI silently
drops any field that is not in the response model, which would hide unreadable
files from the UI.

## Rules

Rules are self-describing classes in `services/rules.py` registered in
`REGISTRY`; the registry spec is served to the UI at `/api/rules/registry`,
so adding a rule type requires no frontend changes. Wildcards: `*` = any run
of characters, `?` = one character. REPLACE substitutes its replacement text
literally (no capture references); PARSE FILENAME is how a wildcard capture
gets assigned to a field. Fields can be any tag field from `app/fields.py` or
a pseudo-field (`filename`, `stem`, `ext`, `folder_name`, `folder_path`);
writing `filename` renames the file.

A param may be flagged `"required": true` in the rule's schema. The UI keeps
its commit button disabled until those are filled in, and the engine refuses
the same cases defensively (REPLACE with an empty *Find*, for instance, would
otherwise match at every character boundary).

## Notes

- MP3 files are written as ID3v2.3 (UTF-8) and ID3v1 tags are removed on
  save to avoid stale duplicates.
- WMA/ASF is read-only (mutagen limitation); everything else the app lists
  as writable can be edited.
- Presets live in `~/.config/yame/presets.json` (override with the
  `YAME_CONFIG_DIR` env var — the Tauri build will point it at the
  per-user app-support folder). `GET /api/health` reports the resolved path.
- **Renames are conservative.** A target name that already ends in a known
  audio extension is used as-is; anything else keeps the original file's
  extension, so "Mr. Brightside" becomes "Mr. Brightside.mp3" instead of an
  extensionless file that folder listings would stop finding. A target that
  exists, is empty, or contains a path separator is refused with a warning and
  the file stays where it is — a tag value like `AC/DC` must never move a file
  out of its folder. `write_fields` returns a `WriteOutcome` carrying the path
  the file actually ended up at.
- `YAME_PORT` overrides the port; otherwise 8000 is used when free and an
  ephemeral port when it is not. The chosen port is announced on stdout as
  `ENGINE_PORT=<n>` and written to `<config_dir>/engine.port` when the server
  *starts*, so importing the app (in tests, for example) has no side effects.
